# One named Target Vessel in the Game Snapshot

Rendezvous and docking need another vessel, and the Game Snapshot carried none. A Mission now has at most one **Target Vessel**, and the snapshot carries one compact entry for it. A Mission without one pays no tokens for it.

- **The entry.** `target` in the Game Snapshot: name, body, situation, the orbit's elements at the snapshot time (apoapsis, periapsis, inclination, eccentricity, semi-major axis, LAN, argument of periapsis, mean anomaly at epoch and epoch), and its free docking ports as counts by size (`"free_ports":{"size1":2}`). A free port with a kOS name tag adds the tag and its size (`"port_tags":{"fore":"size1"}`). Only a port in the `Ready` state is free. The recording JSON also writes the vessel's `persistentId`; Claudia's turns leave it out. The entry goes in the per-turn snapshot, in both the full and the dynamic form (#256). It is never in the cached prefix.
- **Where the target comes from.** It is chosen once, when the Mission starts. KSP's target (`vessel.targetObject`) comes first. With none, the mod looks for a vessel the Mission Goal names, among the vessels in the game the Craft Check saw (the editor has no KSP target, so a Mission started there takes only a named one). It takes the longest whole-word name, in any case. Names under three letters never match, and debris, flags, asteroids and Kerbals on EVA are skipped. A vessel named as the craft is (an earlier flight of it) is never chosen, and a name that several vessels share gives no target; the Mission log says why. The Mission keeps the target's `persistentId` and name, the save keeps them as `targetVesselId` and `targetVesselName`, and the Mission window shows the name under the Mission Goal. A Child Vessel can be the Target Vessel, for example when re-docking with a dropped lander or tug. A vessel is never its own target.
- **Read live.** The adapter reads the target by `persistentId` on every Game Snapshot. That includes the block-internal calls' own snapshots (ADR 0006), so a block sees where the target is now. The core keeps the entry only for the target of the Mission in play. It drops one for any other vessel, and every entry when the Mission has no target. A Mission Plan waits for a snapshot that has read a target the goal named, if that vessel is still in the game.
- **No change to the script gates.** The premise in #453 that scripts can't read other vessels was wrong. The Script Check (`ForbiddenList.cs`) and ADR 0003's runtime gates refuse only *changes* to other vessels. Reading `TARGET`, and `SET TARGET TO`, already pass, and Mission Scripts keep them. A Mission Script's own `DOEVENT` or any other change on another vessel's part stays refused.
- **The bundled program on the target.** The mod may start a bundled program (`dock_hold`, #456) on the Target Vessel's kOS processor. That is the mod acting, not a Mission Script, so ADR 0003's gates are unchanged. Claudia's scripts never run on the Target Vessel.

**Amendment (dock_hold as built, #456):** `dock` asks the mod for the hold through `ADDONS:CLAUDIA:DOCKHOLD`, a block-internal call the Script Check refuses outside the Core Library. The mod starts `dock_hold` when the Target Vessel is loaded and has a kOS processor, electric charge and a link to the craft (aboard) or home (remote), by the Child Vessel link test. The program is compiled from the mod's own text with only the two ports' kOS uids put in, and runs under ADR 0003's runtime gates as an unkeyed run; it changes only its own vessel and reads the craft, so no gate rule changed. The mod stops it on `dock`'s block result and whenever the craft's run ends. A hold that ends on its own before then (a gate trip, lost power, an error) is a fault: `dock` reads it through `DOCKHOLDSTATE`, backs off and fails, and the Debrief follows. A refused start (a busy processor) leaves the target passive. kOS messaging stays forbidden.

**Amendment (chosen before Start, #643):** this replaces "Where the target comes from" on the order and the goal rule. Only a Mission Goal that asks for rendezvous or docking, or names a vessel other than by the craft's own name, has a Target Vessel; for any other goal KSP's target is ignored, so one left from an earlier flight can't slip into a landing. The order is the player's pick, then the vessel the goal names, then KSP's target. The start form (VAB/SPH and Flight) shows a Target Vessel line under the Mission Goal as it is typed, from the core's one choice function, which Start runs too: the target as name · body · situation, or why there is none, the same reason the Mission log gives (the vessels sharing a name, the craft's own name, no vessel matches, Clear). **Choose** lists the vessels the player may pick: not debris, flags, asteroids, Kerbals on EVA, the craft, one named as the craft is, or one whose name another vessel shares (kOS reads the target by name, #655), those at the craft's own body first, then by name. **Clear** leaves the Mission with none; **Auto** goes back to the mod's choice. A pick stays through goal edits. The target joins the craft and the goal in the Craft Check's change detection, so a changed target makes Start check the craft again, and the check judges port sizes against that target. A landed or splashed target is offered and chosen; for a goal that asks for rendezvous or docking the line adds "landed: rendezvous and docking need it in orbit" (mod text, not a Craft Check rule). The pick is not a setup value saved as the next Mission's defaults (#639). Changing the target after Start is its own ticket.

**Amendment (changed after Start, #661):** between sequences (the stages where Mission Settings can be edited; never while Running or a request is out), the Mission window offers Choose and Clear under the pinned goal, for a goal that needs a target, with the start form's list and choice function. The Mission takes the new target (or none) at once, so the adapter reads it into the next Game Snapshot and the save keeps it as `targetVesselId`/`targetVesselName`. Before the first Mission Plan nothing more happens. Otherwise the pending plan becomes Re-plan ("The Target Vessel has changed (now Tug)"), saved as `targetChange`. Re-plan waits for a snapshot that has read the new target, runs the Craft Check's target rule on it (a goal that docks: a port of a size the target has free; the rest of the Craft Check doesn't read the target, so no Claude check is sent) and asks Claudia for a revised Mission Plan with what it found, dropping a pending Sequence Plan. A pending Mission Plan takes that Re-plan at once. Under Auto Mode the Re-plan is taken and the revision approved like any other (ADR 0009): a Mission records that the player approved a Mission Plan (`missionPlanApproved`), so a revision is never taken for the first one when a dropped Sequence Plan brings the count of proposed sequences back to 0. The request's words are per-turn, so the cached prefix is unchanged.

**Amendment (a landed target's position, #662):** a landed or splashed Target Vessel's entry adds `lat`, `lng` (degrees, to 5 places, about a metre) and `alt` (m above sea level, to 0.1 m), read live like the rest; an orbiting target's entry is unchanged, so it pays nothing more. The orbit stays in the entry. `TARGETVESSEL` keeps its "landed, not in orbit" error for such a target, so `rendezvous` and `dock` still refuse it, and adds `name`, `body` (the body it is on) and `lat`, `lng`, `alt`. `land`'s target `"vessel"` reads them before any burn and aims `vessel_offset` (default 200 m, at least 50) beside the vessel, across the ground track, so a miss along the track still passes it; the slope divert is held to 0.7 x vessel_offset - 50 m (90 m by default) so the site stays 50 m across the track, the slope divert and the Underhang clearance never move the site within 50 m of it, and the site never moves for terrain. The script gates are unchanged: land only reads the target. About 15 tokens more on a turn's snapshot while the Mission has a landed target; the cached prefix is unchanged (land's other docs were trimmed to pay for the option).

We rejected listing every vessel in the same sphere of influence (more tokens on every turn, #212, and more to guard), and rendezvous only with Child Vessels (too narrow). The cost: one entry of about 150 tokens (443 characters for a full-precision orbit), sent on a turn's snapshot only when the Mission has a Target Vessel. The cached prefix is unchanged.

Decided on #453 (spec #435, Phase 3).
